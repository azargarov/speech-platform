# Architecture

Gateway → STT worker; Gateway → TTS worker. Workers have no calls or imports between them. Each process is independently buildable and configurable. Shared Python code contains HTTP/configuration mechanics only; each worker can be deployed without starting the other. One worker image supports separate entry points.

Gateway owns public versioned contracts, authentication, validation and routing. Provider implementation, model registry and model lifecycle belong to their respective workers. Public model/voice IDs are platform aliases. The Gateway forwards an STT alias unchanged; STT resolves that alias to an immutable artifact and backend. Public and internal contract types do not name faster-whisper or any engine.

In M01 GET /healthz, GET /readyz and GET /metrics exist. Gateway readiness is an injected interface; the foundation implementation returns false. Worker readiness is false because no provider is installed. M02/M03 make worker readiness depend on a loaded usable model, lifecycle state and enabled admission. Temporary queue saturation is reported as overload (429) and does not change readiness. Loading, draining and fault-latched model states are not ready. M04 will make gateway readiness depend on authentication configuration, routing initialization and required worker readiness. Liveness remains independent of downstream model health.

Go uses explicit constructor arguments, local configuration values and an HTTP transport helper. Python worker code stays modular; STT inference is separate from shared TTS transport. No mutable application globals. Go propagates signal context to bounded server shutdown. STT carries a monotonic deadline through upload, admission, decoding and inference. Disconnect/deadline removes queued work immediately; active work receives cooperative cancellation, then the supervised inference child is terminated after a configured grace. Capacity remains owned until completion or confirmed child exit. M01 does not claim inference cancellation is implemented; M02 design details are in [m02-stt-design.md](m02-stt-design.md).

Streaming is reserved in contracts and capability metadata. A future ADR must define framing, backpressure, disconnect propagation and auth before streaming activation; current stream=true requests are contractually rejected once routing exists. No streaming transport in M01.

Worker process lifecycle and model lifecycle are separate. A healthy worker control process may remain live while its model is loading or fault-latched; model usability drives readiness. M02 limits each worker instance to one resident model and one active job, with a bounded FIFO queue. This is a release constraint, not a permanent architecture restriction. No transcripts, audio or request payloads are logged. Worker lifecycle events and Gateway logs are structured JSON. Prometheus metric names planned: speech_requests_total, speech_request_duration_seconds, speech_inflight_requests, speech_provider_ready. GET /metrics exposes the Prometheus speech_ready gauge; request instrumentation will accompany actual routing.

Deployment uses separate internal Compose networks: Gateway and STT share `stt_private`; Gateway and TTS share `tts_private`; STT and TTS do not share a network. Workers publish no host ports, and only Gateway publishes a host port, loopback-bound by default. Gateway is intentionally dual-homed and is the trusted caller boundary for both workers. This segments network reachability but does not authenticate Gateway, defend against host/Docker administrators, isolate shared host resources, or prove runtime deployment behavior. Ollama and Dify networking is unchanged. See accepted [ADR 0009](../adr/0009-worker-network-reachability.md). Models are provisioned offline into read-only storage. M02 requires separate portable application settings and deployment settings. Device discovery is adapter-owned; CPU and CUDA are supported by the same faster-whisper adapter. GPU free-memory checks are observations and admission heuristics, not reservations. No worker allocates, evicts or reloads another service's models.

Configuration is strict YAML with unknown/duplicate fields rejected. Required fields have no implicit application defaults. Sample values are deployment data. Config changes require restart. Secrets must eventually be read from mounted secret files, never committed. M01 has no authentication configuration or enforcement; M04 introduces both with public routing.

Structure deviations: services/worker contains shared transport; three OpenAPI documents separate public and private boundaries; scripts contains GPU-free acceptance checks. No benchmark source was fabricated when remote access failed.
