# Architecture overview

SpeechPlatform is an authenticated HTTP service platform. It exposes speech and text operations through one Gateway while keeping speech inference in independent STT and TTS workers. Client applications and product-specific business logic are outside this repository. The [architecture principles](principles.md) and [ADRs](../adr/) capture stable boundaries and accepted decisions; this overview describes the current implementation.

## Components and capabilities

- **Gateway:** owns public HTTP routes, bearer authentication, request validation, request IDs, worker/provider routing, admission limits, and health/readiness endpoints. It does not perform speech inference.
- **STT worker:** serves local Faster-Whisper transcription and model lifecycle. Optional Groq audio transcription is implemented in the Gateway and controlled separately by Gateway configuration, credentials, and per-request audio consent.
- **TTS worker:** serves local VoxCPM2 speech synthesis and a bounded SSML subset. The public API exposes only its configured default voice and no provider/model selection.
- **Text transformation:** the Gateway calls configured text providers, currently local Ollama Qwen and optional Groq-compatible models. Translation is a text transformation option. Requests may replace the default system prompt for that request only.

Gateway, STT and TTS are independently selectable for installation using the existing Make and Compose tooling. Gateway capability flags independently enable local STT and TTS routes; text transformation has its own enablement and configured model list. Disabled operations return an unavailable response while preserving authentication. Readiness checks required enabled workers, not disabled ones. Deployment selection does not change capability settings. See the [installation guide](../operations/installation.md).

The Gateway currently enables `local-qwen`, `groq-qwen` and `groq-gpt-oss` in [`configs/gateway.yaml`](../../configs/gateway.yaml). The configured policy is ordered, with local Qwen first, and `allow_cloud: true`. The CLI is local-only by default and requires `--allow-cloud` to make cloud models eligible. In the public API, however, `local_only` defaults to `false`; API clients must explicitly set it to `true` whenever they require local-only routing. Cloud availability still depends on Gateway policy and credentials. With no alias selected, later eligible models may be attempted after an earlier provider failure. An explicitly selected model never falls back. `fallback_occurred` reports whether a later candidate supplied the response. Groq STT is disabled in the canonical configuration and requires separate audio consent if enabled. No Groq TTS integration exists.

The public text API supports Raw, Written, Polite and Diplomatic modes, Normal, Concise and Structured formats, and translation target codes `en`, `sv`, and `ru`. Raw without translation is exact pass-through and only supports Normal. These are implemented request options, not quality guarantees. M07B2's finite qualification found material semantic, language-retention and format failures; no model was accepted as a general winner. See the [M07B2 evidence](../milestones/M07B2/verification.md).

## Configuration and deployment

`configs/gateway.yaml` is the canonical tracked Gateway runtime configuration for root Compose. `configs/stt.yaml` and `configs/tts.yaml` remain service-owned worker configurations, with deployment-specific STT settings in their separately documented files. Strict loaders reject unknown fields. `.env` contains operator deployment values and the Gateway bearer token; provider API keys are supplied through `private/cloud.env` or another protected file selected by `GATEWAY_SECRETS_FILE`. Secrets and qualification evidence are not authoritative tracked configuration.

Root Compose publishes only the Gateway port, loopback-bound by default. Gateway has an outbound bridge for provider HTTPS and separate private connections to enabled workers. STT and TTS remain on their individual internal networks. When configured for local text inference, Gateway also joins the existing external Ollama private network. Ollama is managed independently; SpeechPlatform checks and uses it but does not create, restart or upgrade it. Model artifacts are provisioned separately and mounted read-only rather than downloaded at runtime.

Component selection controls which images are built and services updated. For an enabled worker omitted from an update, preflight verifies the existing service is owned by the SpeechPlatform Compose project, compatible and healthy. An enabled worker that is missing must be selected for deployment or repaired before Gateway can be updated. Strict integrity checks apply to selected worker artifacts and images. Installation retains exact prior image IDs for rollback; see the [installation and rollback procedures](../operations/installation.md).

## Request handling and operations

Public speech and text operations require bearer authentication, including loopback deployments. Health and readiness routes are unauthenticated. `/healthz` reports Gateway process liveness; `/readyz` checks the enabled STT/TTS worker dependencies and ignores disabled capabilities. It does not establish text-provider or cloud-credential availability; those are surfaced when a provider is selected. Worker model loading is lazy; readiness reflects whether the worker can accept work, not whether a model is resident. Warmup is explicit and can change model residency.

Gateway and worker logs contain request correlation and operational metadata but do not log audio, transcripts, request text, generated text, credentials or custom prompt contents. Qualification reports retain protocol/provider metadata; `--evidence` explicitly stores request/response content. The qualification CLI's `--debug` can collect bounded local Compose logs. Protect and remove sensitive qualification artifacts when no longer needed.

The [OpenAPI contract](../../api/openapi/public-v1.yaml) describes versioned public operations. `/healthz`, `/readyz`, and `/metrics` are operational routes outside that contract. The [qualification capability matrix](../operations/qualification-capabilities.md) documents tool/API coverage and known contract-runtime differences. Technical HTTP success does not establish semantic correctness or natural language quality.
